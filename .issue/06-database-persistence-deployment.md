# [بالا] تنظیمات پایگاه‌داده و ماندگاری داده با راهنمای استقرار ناسازگارند

## شواهد

- `backend/prisma/schema.prisma:8-11` provider را `sqlite` تعیین می‌کند؛ مهاجرت `backend/prisma/migrations/20261001095815_init/migration.sql:2-4` از `AUTOINCREMENT` و قالب SQLite استفاده می‌کند.
- `backend/.env.example:6` نمونهٔ اتصال به فایل SQLite را نشان می‌دهد.
- `backend/README.md:8-16,135-156` راه‌اندازی را با PostgreSQL 16 توضیح می‌دهد؛ `backend/docker-compose.yml:4-16` PostgreSQL را بالا می‌آورد اما backend service/volume برای SQLite ندارد.
- `backend/Dockerfile:24-51` تصویر production را با `npx prisma migrate deploy` بالا می‌آورد؛ `/app/uploads` می‌سازد ولی volume یا mount برای فایل دیتابیس/آپلود تعریف نمی‌کند.
- `backend/prisma/migrations/migration_lock.toml` نیز provider را `sqlite` ثبت کرده است. در بررسی محلی ۲۰۲۶-۱۰-۰۳، Prisma Client تولیدشده و تنظیم توسعهٔ محلی از نوع PostgreSQL بودند؛ این دو نشانهٔ محلی، ناسازگاری schema و مهاجرت‌های نسخه‌شده را برطرف نمی‌کنند. هیچ مقدار اتصال، رمز یا مسیر محلی در این گزارش ثبت نشده است.
- در همان بررسی، نه سرور بک‌اند روی پورت تنظیم‌شده پاسخ‌گو بود و نه سرویس پایگاه‌دادهٔ تنظیم‌شده روی loopback اتصال TCP می‌پذیرفت. فایل SQLite متناظر نیز در workspace پیدا نشد؛ بنابراین شمار رکوردهای کلینیک و وضعیت دادهٔ واقعی قابل احراز نبود.

## بازتولید در محیط ایزوله

راهنمای README را با URL PostgreSQL دنبال کنید: Prisma با provider SQLite این URL را نمی‌پذیرد. اگر به‌جای آن `.env.example` استفاده شود، دیتابیس در فایل داخل filesystem کانتینر ساخته می‌شود؛ با جایگزینی کانتینر، فایل دیتابیس و `/app/uploads` مگر با mount بیرونی از دست می‌روند.

تا وقتی provider، Prisma Client تولیدشده، مهاجرت‌ها و مقصد واقعی اتصال همسان نشده‌اند، اجرای `prisma migrate` یا `prisma:seed` روی دادهٔ موجود و ورود کلینیک‌ها ایمن نیست. `prisma generate` دادهٔ پایگاه‌داده را تغییر نمی‌دهد، اما در وضعیت فعلی کلاینت PostgreSQL محلی را با کلاینت SQLite ناهمخوان با تنظیم توسعه جایگزین می‌کند. هیچ‌یک در این بررسی اجرا نشد. اسکریپت seed کلینیک ایجاد نمی‌کند و بخش‌هایی از آن برای داروخانه و دارو از `create` استفاده می‌کنند؛ پس برخلاف توصیف کلی راهنما، اجرای دوبارهٔ آن را نمی‌توان برای واردکردن کلینیک‌ها بی‌خطر فرض کرد.

## اثر و معیار رفع

استقرار طبق راهنما شکست می‌خورد یا دادهٔ کاربران/سفارش‌ها و تصاویر در انتشار بعدی حذف می‌شود. برای مسیر production که PostgreSQL در راهنما و Compose آمده، مالک بک‌اند باید schema، مهاجرت‌ها، Prisma Client، تنظیم اتصال، README و Docker را با PostgreSQL همسان کند؛ دادهٔ موجود و مسیر مهاجرت آن را نیز روشن سازد. سپس ماندگاری و backup را با restart/recreate واقعی تأیید کند. پیش از این همسان‌سازی و تعیین مقصد محلی، ورود حتی یک‌بارهٔ کلینیک‌ها انجام نشود. این بررسی هیچ تغییری در واحد قیمت/محصول یا جریان OTP ایجاد نکرده است.

## محیط آزمایشی مستقل — ۲۰۲۶-۱۰-۰۴

بدون تغییر تنظیم PostgreSQL فعلی یا داده‌های قبلی، کپی خارج مخزن با provider SQLite مطابق schema/migrationها، Prisma Client تازه و دو migration اجرا شد. فایل دیتابیس و آپلودها ماندگار و خارج DocumentRoot Apache هستند؛ integrity_check سالم است. Redis واقعی با رمز و volume ماندگار فقط از loopback منتشر شد. این آماده‌سازی فقط محیط آزمایشی را راه‌اندازی می‌کند؛ انتخاب و ماندگاری provider رسمی استقرار و backup/بازیابی هنوز با مالک بک‌اند است. فیلترهای mode ناسازگار و entrypoint production مخزن در پرونده‌های ۱۸ و ۲۰ ثبت شدند. نوشتن واقعی پس از OTP و ماندگاری رکوردهای ایجادشده پس از restart هنوز پذیرفته نشده است.
