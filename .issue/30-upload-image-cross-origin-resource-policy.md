# [متوسط] سیاست same-origin تصویر آپلودشده را در فرانت و ادمین با origin جدا مسدود می‌کند

## وضعیت کاندید محلی — ۲۰۲۶-۱۰-۱۱

شواهد اولیهٔ زیر تاریخچه‌اند. کاندید محلی `uploadStaticHeaders` را فقط روی پاسخ static تصویر JPEG/PNG/WebP ثبت می‌کند و سیاست این پاسخ‌ها را `same-site` می‌گذارد. API، فایل غیرتصویری و پاسخ فایل ناموجود سیاست پیش‌فرض `same-origin` را نگه می‌دارند. هیچ آزادسازی عمومی CORS یا guard انجام نشده است.

| محدودبودن override به raster مجاز | `upload-static-headers.spec.ts` با HTTP واقعی در harness ایزوله | موفق محلی |
| تصویر SVG / غیرتصویری / فایل ناموجود / API | همان تست؛ هدر پیش‌فرض حفظ می‌شود | موفق محلی |

وضعیت فعلی: **اصلاح محدود source و پذیرش HTTP محلی؛ پذیرش بصری و VPS باز**. `same-site` دسترسی از هر سایت دیگر را مجاز نمی‌کند؛ proxy هم‌مبدأ نیز جای آزمون تنظیم دامنهٔ نهایی را نمی‌گیرد. هیچ commit، push یا استقرار این فاز انجام نشده است.

## شواهد

- `backend/src/main.ts:25`، `helmet.default()` را بدون تنظیم جداگانهٔ سیاست منابع ثبت می‌کند. پاسخ فایل آپلودشده دارای `Cross-Origin-Resource-Policy: same-origin` است.
- `backend/src/main.ts:43-45` فایل‌های آپلودشده را با پیشوند `/uploads` به‌صورت static ارائه می‌کند؛ این پاسخ نیز هدر عمومی بالا را دریافت می‌کند.
- در آزمون واقعی محلی، آپلود تصویر حیوان در دیتابیس و فضای فایل ذخیره شد و دریافت فایل از API روی پورت ۳۰۰۰ پاسخ ۲۰۰ داد. آدرس `src` تصویر به همان فایل اشاره می‌کرد، اما در مرورگر فرانت روی پورت ۵۱۷۳، `naturalWidth` صفر بود و سیاست same-origin نمایش تصویر را مسدود کرد. تفاوت پورت، origin متفاوت ایجاد می‌کند. ادمین محلی روی پورت ۵۱۷۴ نیز معماری origin جدا دارد؛ پذیرش نمایش آن پس از اصلاح لازم است.
- ناسازگاری مستقل ساخت URL تصویر برای API base نسبی در فرانت، در کاندید محلی اصلاح و با تست پوشش داده شده است. رفع URL، هدر محدودکنندهٔ پاسخ سرور را تغییر نمی‌دهد و رفع این پرونده محسوب نمی‌شود.

## اثر و محدوده

رابط می‌تواند ذخیرهٔ موفق تصویر را گزارش کند، اما پیش‌نمایش یا تصویر ذخیره‌شده دیده نشود. اگر در production نیز میزبان فایل و میزبان مشتری/ادمین متفاوت باشند، همین ناسازگاری ممکن است رخ دهد؛ این اثر هنوز روی انتشار VPS فعلی تأیید نشده است. این یافته شکست آپلود یا ازبین‌رفتن فایل را نشان نمی‌دهد.

## اصلاح محدود پیشنهادی

برای پاسخ فایل‌های مجاز `/uploads`، سیاست مورد نیاز منابع متعلق به سایت مشخص شود. اگر فایل‌ها از originهای جدا اما متعلق به همان سایت ارائه می‌شوند، override محدود `Cross-Origin-Resource-Policy: same-site` روی همین پاسخ‌های static بررسی شود؛ هدر پیش‌فرض سایر مسیرها باقی بماند. راه دیگر، ارائهٔ فایل از proxy همان origin رابط است. انتخاب باید با تنظیم واقعی استقرار هماهنگ شود.

این پیشنهاد مجوز حذف سراسری Helmet، آزادکردن CORS، تغییر guardهای JWT/نقش یا عمومی‌کردن یک API خصوصی نیست. هر سیاست دسترسی موجود به فایل نیز باید حفظ شود.
