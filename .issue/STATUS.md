## پذیرش محلی MySQL و محدودهٔ تحویل فرانت — ۲۰۲۶-۱۰-۰۴

روی 4cf0f77، MySQL 8.4.11 واقعی با مهاجرت پایه اجرا شد؛ روابط ۲۸ مدل، متن فارسی، مبالغ، uniqueness، cascade و rollback تست شدند. بکاپ در دیتابیس جدا بازیابی و ماندگاری پس از restart ثابت شد. ده کلینیک تحقیق‌شده با isVerified=false وارد MySQL محلی شدند؛ اجرای دوم صفر درج و ده skip داشت. فهرست و ده جزئیات ۲۰۰ دادند؛ جست‌وجوی آرامیس موفق بود. این‌ها پذیرش سرور Ubuntu یا تمام فیلترهای فارسی نیستند. هیچ پیامک واقعی، تغییر VPS یا دورزدن OTP انجام نشد.

درخواست‌های ناشناس به admin/me، users/me، pets، admin/clinics و admin/sms/logs همگی ۴۰۱ شدند. در درخواست‌های خواندنی بررسی‌شده هدر Set-Cookie نبود؛ پذیرش نشست authenticated هنوز انجام نشده است. فرانت/ادمین ورود واقعی و Bearer contract را حفظ کرده‌اند. قالب SMS.ir شمارهٔ 448272 طبق اعلام مالک تا راه‌اندازی سایت و تأیید سرویس‌دهنده آماده نیست. پرداخت mock فقط در تست محلی با اجازهٔ صریح مالک فعال است؛ نه در production.

پروندهٔ ۲۱ روی MySQL جدید دوباره با GET /medicines?page=1&limit=20 پاسخ ۵۰۰ داد؛ محصولات، داروخانه‌ها، کلینیک‌ها و مرجع‌ها پاسخ ۲۰۰ دارند. پروندهٔ ۰۶ از نظر مهاجرت/بکاپ/ماندگاری محلی شاهد دارد؛ انتقال دیتابیس به VPS هنوز انجام نشده است. پروندهٔ ۱۸ از نظر حذف mode و جست‌وجوی نمونه شاهد دارد؛ پذیرش جامع جست‌وجو در deployment باز است.

فرانت ۱۹۸ تست / ۳۲ فایل، ادمین ۲۵ تست / ۶ فایل و lint/typecheck/build موفق دارند؛ بک‌اند ۱۷۷ تست واحد کنترل‌شده / ۲۷ suite دارد. تست‌های mock جای پیامک/پرداخت واقعی را نمی‌گیرند. تمام داده‌های تحقیق و تنظیم خصوصی خارج مخزن‌اند؛ کامیت کد، دادهٔ ده کلینیک را به سرور منتقل نمی‌کند. محصولات بنا به دستور جدید مالک فعلاً وارد نمی‌شوند.

## پذیرش VPS و انتشار اولیه — ۲۰۲۶-۱۰-۰۶

- سایت و ادمین با نسخهٔ فرانت تأییدشده روی `https://drgupet.ir` و `https://admin.drgupet.ir` منتشر شدند. پاسخ HTTPS و فایل‌های JS/CSS از اتصال خارجی نیز ۲۰۰ بود؛ HTTP به HTTPS هدایت می‌شود. تمدید خودکار Certbot و hook بازخوانی Nginx تنظیم شد.
- خطای احراز هویت MySQL با حفظ volume موجود و پشتیبان سرد قابل‌خواندن رفع شد؛ بکاپ SQL پس از بازیابی دسترسی هم موفق بود. تست مستقیم MySQL و Prisma موفق بود. مهاجرت پایه اعمال شد و ۳۰ جدول، شامل جدول‌های واسط/مهاجرت، موجود است.
- کانتینرهای backend، MySQL و Redis healthy بودند؛ backend بدون restart مجدد روی loopback اجرا شد. این اجرای آزمایشی، پذیرش production عمومی نیست.
- نوشتن/خواندن user، product/variant، clinic و medicine، متن فارسی، مبلغ و روابط در تراکنش واقعی MySQL موفق بود؛ rollback کامل شد و هیچ رکورد آزمایشی باقی نماند. این تست ORM است، نه درج authenticated از رابط ادمین.
- API داخلی محصولات، مرجع‌ها، کلینیک و داروخانه ۲۰۰؛ admin/users، admin/clinics و admin/products ناشناس ۴۰۱؛ شماره نامعتبر و OTP درخواست‌نشده ۴۰۰؛ برای origin نامعتبر مجوز CORS داده نشد. نشست authenticated، کوکی ورود و آپلود مجاز هنوز پذیرفته نشده‌اند.
- پروندهٔ ۲۱ روی VPS نیز با فهرست دارو پاسخ ۵۰۰ دارد. هیچ محصول، کلینیک یا کاربر واقعی در دیتابیس این VPS درج نشده است؛ داده‌های ده کلینیک همچنان فقط در محیط محلی قبلی موجودند.
- کلید SMS در فایل خصوصی هماهنگ و قالب با تأیید مالک روی 448272 تنظیم شد؛ OTP ثابت حذف شد. یک درخواست واقعی با پاسخ SMS.ir برابر HTTP 400 / status 113 / «قالب یافت نشد» شکست خورد. ورود موفق یا تحویل پیامک اثبات نشده است؛ مالک باید پس از انتشار سایت تأیید قالب را درخواست کند.
- API عمومی عمداً ۵۰۳ و Swagger عمومی ۴۰۴ است. دریافت درگاه نیازمند مجوز است؛ نیاز به حالت production با پرداخت غیرفعال در [پروندهٔ ۲۵](25-production-without-payment-provider.md) ثبت شد. هیچ mock یا بک‌اند development از Nginx منتشر نشده است.
- OpenSSL در هر دو مرحلهٔ Dockerfile این VPS اصلاح شده است؛ این تغییر محلی سرور باید هنگام همگام‌سازی بعدی حفظ شود. source سرور c19d9e8 و remote e8184f5 است؛ اختلاف فرانت/ادمین صفر بود. انتشار شامل build همان فرانت تأییدشده با API base برابر `/api/v1` است، نه ادغام یا کامیت تازه.

## وضعیت فعلی و شواهد پذیرش — ۲۰۲۶-۱۰-۰۷

این بخش نتیجهٔ بررسی تازه را ثبت می‌کند؛ گزارش‌های تاریخ‌دار بالا تاریخچه‌اند. سلامت API، وجود داده در MySQL و موفقیت تست محلی، به‌تنهایی پذیرش ورود یا عملیات احراز هویت‌شده نیستند.

| محدوده | نتیجهٔ فعلی | محدودیت پذیرش |
| --- | --- | --- |
| VPS و API | کانتینرهای backend، MySQL و Redis سالم؛ backend حدود ۲۳ ساعت فعال با restart برابر صفر؛ health عمومی پاسخ ۲۰۰ دارد | بازبینی فعلی خواندنی بود؛ استقرار نسخهٔ جدید در این نوبت انجام نشده است |

پذیرش ورود مشتری و ادمین، دسترسی نقش پس از ورود، نشست authenticated و کنترل کوکی، آپلود مجاز و CRUD ادمین باز است. پاسخ ۴۰۱ ناشناس یا وجود حساب در MySQL جای این پذیرش‌ها نیست. کلیدها، شماره‌های کاربران و تنظیمات خصوصی در گزارش درج نمی‌شوند.

همگام‌سازی release هنوز باز است: تغییرهای محلی و تفاوت‌های VPS باید با حفظ diff، پشتیبان دیتابیس و buildهای قبلی بررسی شوند. پس از پیش‌نمایش و تأیید مالک، commit/push و استقرار همان Git SHA با مهاجرت‌های لازم انجام می‌شود؛ demo seed جزو انتشار production نیست. این به‌روزرسانی مستندات مجوز commit، push یا deployment نیست.
