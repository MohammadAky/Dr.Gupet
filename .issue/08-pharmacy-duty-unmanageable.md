# [متوسط] وضعیت کشیک داروخانه در قرارداد مدیریت تعریف نشده است

## شواهد

- `backend/prisma/schema.prisma:400` فیلد `Pharmacy.onDuty` را با پیش‌فرض `false` دارد.
- `backend/src/modules/pharmacies/pharmacies.service.ts:18-40,53-54` endpoint عمومی با `onDuty` فیلتر می‌کند و این مقدار را در پاسخ برمی‌گرداند.
- `backend/src/modules/pharmacies/admin-pharmacies.controller.ts:56-76,92-113` شکل body ساخت و ویرایش، `onDuty` ندارد.
- `backend/src/modules/pharmacies/pharmacies.service.ts:167-211` مسیر create فیلدهای دریافتی را صریحاً می‌نویسد و `onDuty` را حذف می‌کند. مسیر update شیء body را مستقیماً به Prisma می‌سپارد؛ بنابراین ممکن است PATCH ارسالی خارج از قرارداد، در زمان اجرا `onDuty` را ذخیره کند. این رفتار آزموده و تضمین نشده است.

## بازتولید در محیط ایزوله

با نشست مدیر، یک داروخانه را با `onDuty:true` بسازید؛ سرویس create مقدار را به Prisma نمی‌فرستد و رکورد با پیش‌فرض `false` ساخته می‌شود. PATCH با `onDuty` در قرارداد تایپ‌شدهٔ کنترلر/سرویس نیست و رفتار آن باید با تست API تعیین شود؛ فرانت نباید روی پذیرش اتفاقی فیلد حساب کند.

## اثر و معیار رفع

مدیر مسیر مستند و قابل اتکایی برای تنظیم کشیک ندارد و فیلتر عمومی ممکن است نتیجهٔ ناقص بدهد. `onDuty` را در DTO معتبر و create/update پشتیبانی کنید؛ تست API ایجاد، تغییر true→false و فیلتر عمومی را اضافه کنید. تا رفع، فرانت مدیریت نباید وانمود کند تغییر کشیک ذخیره می‌شود.
