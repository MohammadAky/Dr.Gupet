# [متوسط] اعتبارسنجی عدد صحیح تعداد سبد و تنظیمات مالی

## شواهد — بررسی ثابت ۲۰۲۶-۱۰-۰۳، مبنای `865f29b`

- DTOهای افزودن/ویرایش سبد از `IsNumber` استفاده می‌کنند؛ `quantity` در Prisma از نوع `Int` است. مقدار کسری می‌تواند از اعتبارسنجی عبور کند و در ذخیره‌سازی شکست بخورد. سقف تعداد فعلی ۲۰ است.
- `backend/src/admin/settings/dto/set-setting.dto.ts` فقط رشتهٔ غیرخالی می‌خواهد. `SettingsService.getNumber` هر مقدار finite، شامل هزینهٔ منفی یا کسری، را می‌پذیرد. تنظیم نامعتبر می‌تواند محاسبهٔ سفارش را خراب کند یا به خطای Prisma منجر شود. مسیر تنظیمات محدود به ادمین است؛ ادعای دسترسی کاربر عادی مطرح نیست.

## معیار رفع

- [ ] تعداد سبد: عدد صحیح امن در بازهٔ ۱ تا ۲۰؛ مقدار کسری، منفی، نامتناهی و خارج بازه با خطای ۴۰۰ رد شوند.
- [ ] هزینهٔ ارسال و آستانهٔ ارسال رایگان: تومان صحیح امن و غیرمنفی؛ زمان انقضا: عدد صحیح مثبت با سقف معقول.
- [ ] مقدار نامعتبر در زمان ذخیرهٔ تنظیمات رد شود؛ سفارش بعدی از تنظیم نامعتبر استفاده نکند.
- [ ] تست API با تعداد `1.5` و تنظیم هزینهٔ منفی/کسری اضافه شود.

فرانت تعداد کسری و تنظیمات مالی نامعتبر را محدود می‌کند، اما درخواست مستقیم به تضمین سرور نیاز دارد. تست زنده انجام نشده و کد بک‌اند تغییر نکرده است.
