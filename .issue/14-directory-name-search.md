# جست‌وجوی نام مراکز برای پیشنهادهای سراسری

**نوع:** نیاز قرارداد بک‌اند  
**وضعیت:** باز؛ بررسی کد `main` در `865f29b`، بدون آزمون API زنده  
**اولویت:** متوسط

## شواهد

- `backend/src/modules/clinics/dto/clinic-query.dto.ts` فقط `city`، `province` و `is24h` دارد.
- `backend/src/modules/pharmacies/dto/pharmacy-query.dto.ts` فقط `city`، `province`، `is24h` و `onDuty` دارد.
- جست‌وجوی نام با `q` در این قراردادها تعریف نشده است. هدر مشتری باید بعد از سه حرف، نتایج محصولات، داروها، داروخانه‌ها و کلینیک‌ها را دسته‌بندی کند.

## رفتار موقت فرانت

محصولات و داروها از `q` موجود استفاده می‌کنند. برای هر نوع مرکز، حداکثر پنج صفحهٔ ۵۰تایی از API عمومی خوانده و دو دقیقه در حافظه نگهداری می‌شود؛ نام‌ها با یکسان‌سازی «ی/ک» و حذف علائم جهت/نیم‌فاصله تطبیق می‌یابند. اگر تعداد صفحات بیشتر یا فرادادهٔ صفحه‌بندی غایب باشد، محدودبودن پیشنهادهای مراکز به کاربر اعلام می‌شود. این روش جست‌وجوی کامل پایگاه داده نیست.

## درخواست اجرایی و پذیرش

1. افزودن `q` اختیاری، رشته‌ای و با سقف طول مشخص به هر دو DTO و مستندات API؛ جست‌وجوی substring نام با سیاست روشن یکسان‌سازی حروف فارسی/عربی.
2. حفظ محدودیت رکوردهای عمومی فعال، صفحه‌بندی و فیلترهای موجود؛ query با پارامتر امن ORM اجرا شود. ورودی نامعتبر پاسخ ۴۰۰ بگیرد.
3. `GET /clinics?q=روی&limit=5` و مسیر مشابه داروخانه باید رکورد منطبق را حتی خارج از ۲۵۰ ردیف اول پیدا کنند؛ رکورد غیرفعال نمایش داده نشود.
4. آزمون ترکیب `q` با شهر/استان، ترتیب و فراداده، ورودی فارسی/عربی، نتیجهٔ خالی و سقف طول انجام شود.
5. پس از تأیید قرارداد زنده، فرانت جست‌وجوی مراکز را به `q` سرور وصل کند و مسیر دریافت فهرست محدود حذف شود.

هیچ کد بک‌اند در این درخواست تغییر نکرده است.
