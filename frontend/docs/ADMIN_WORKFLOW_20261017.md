# بازبینی محلی گردش کار ادمین — ۱۷ اکتبر

این مرحله پس از انتشار تأییدشدهٔ `e8da788` اجرا می‌شود. انتشار قبلی روی GitHub و VPS بررسی شد. مالک پس از دیدن طرح، اصلاحات این مرحله را تأیید و ترتیب «اول VPS، بعد GitHub» را صریحاً درخواست کرد. نسخهٔ محلی کامیت می‌شود و همان SHA و build به سرور می‌روند؛ پوش GitHub پس از بررسی سرور انجام می‌شود. هیچ دادهٔ آزمایشی به تولید منتقل نمی‌شود.

## رفتار قابل بررسی

- محصولات: خروجی CSV همهٔ نتایج فیلتر با ستون‌های دلخواه، و ورود مجدد از مسیر «به‌روزرسانی با CSV». شناسهٔ محصول/گزینه یا SKU هدف ویرایش است؛ نام محصول هدف تطبیق نیست. ردیف جدید می‌تواند محصول یا گزینهٔ تازه بسازد. پیش‌نمایش تغییرات پیش از ثبت الزامی است.
- خانهٔ خالی دادهٔ موجود را نگه می‌دارد؛ صفر مقدار واقعی است؛ `__CLEAR__` متن اختیاری را پاک می‌کند. T/F انتشار را کنترل می‌کند. موجودی و timestamp خروجی برای جلوگیری از بازنویسی فروش یا ویرایش هم‌زمان نگه داشته می‌شوند. هر عملیات حداکثر ۵۰۰ ردیف، فایل یک مگابایت و JSON نهایی ۹۰۰ کیلوبایت دارد؛ ثبت تراکنشی است.
- خطای خروجی «numeric string» ناشی از اجرای API قدیمی بود: `export.csv` به مسیر `:id` می‌رسید. API جدید با مسیر ثابت و ترتیب controller صحیح اجرا شد؛ دانلود واقعی از دکمهٔ پنل موفق بود.
- خطای `property status/isActive should not exist` از اعتبارسنجی کل query با DTO صرفاً صفحه‌بندی بود. ده فهرست صفحه‌بندی‌شده به DTO مختص مسیر منتقل شده‌اند؛ منطق سرویس، نقش و محاسبات مالی حفظ شده‌اند. مرجع‌ها، گزارش‌ها و timezone نیز قرارداد query صریح دارند.
- هفت بخش صفحهٔ اصلی مستقیماً قابل انتخاب‌اند؛ پیش‌نویس و تصویرها حین تعویض بخش باقی می‌مانند. این بخش همچنان پیش‌نویس مرورگر/خروجی فایل است و CMS مشترک منتشرشده ادعا نمی‌شود.
- داده‌های مرجع در منوی مستقل‌اند. سفارش‌ها همهٔ وضعیت‌های تعریف‌شده را نشان می‌دهند؛ مراحل بعدی آماده‌سازی/ارسال/تحویل مستقیم انتخاب می‌شوند. تأیید پرداخت و استرداد مسیر مالی جدا دارند؛ بازگشت به عقب/بازکردن سفارش نهایی مجاز نشده است.
- حذف محصول جدول را پنهان نمی‌کند؛ بازخوانی در پس‌زمینه است. جدول ورود CSV عرض ستون مشخص و اسکرول داخلی دارد.
- فروشگاه: تیتر فشرده، فیلتر راست دسکتاپ و کنترل بازشوندهٔ موبایل. برند و نوع حیوان/سن بالای خط کارت؛ پایین کارت قیمت یا «ناموجود» است. برای ناموجود هیچ قیمت فعلی/قبلی نشان داده نمی‌شود. نوع حیوان از رابطهٔ API می‌آید.

## شواهد موجود

- اجرای کامل پیش از اصلاح تازهٔ queryها و کارت‌ها: ادمین ۲۹ فایل/۲۷۷ تست و بک‌اند ۵۸ سوییت/۶۹۲ تست موفق؛ build هر دو موفق. تست‌های تازهٔ هر اصلاح جداگانه ثبت می‌شوند و جای پذیرش تولید نیستند.
- API و دیتابیس واقعی محلی: ورود با رمز حساب موجود، خروجی ۲۰۰، رد ناشناس ۴۰۱، preview بدون نوشتن، ثبت موجودی صفر با حفظ سایر فیلدها، رد snapshot قدیمی ۴۰۹. دو apply هم‌زمان از یک snapshot یک ۲۰۱ و یک ۴۰۹ دادند؛ fixture خصوصی پاک شد.
- دانلود واقعی CSV از پنل و ورود دوبارهٔ همان خروجی تازه، ۶۱ گزینهٔ بدون تغییر را در پیش‌نمایش نشان داد؛ ثبت مجدد دادهٔ مالک انجام نشد. یک خروجی قبلی که در فاصلهٔ بررسی یکی از گزینه‌هایش حذف شده بود به‌درستی رد شد و با خروجی تازه معتبر شد.
- سفارش واقعی آزمایشی محلی: تحویل مستقیم ۲۰۰ و فقط timestamp تحویل؛ دو گذار هم‌زمان یک ۲۰۰/یک ۴۰۹؛ دو لغو هم‌زمان یک ۲۰۱/یک ۴۰۹ و بازگشت موجودی فقط یک‌بار (۸→۱۰). سه سفارش و موجودی‌های قبلی یکسان ماندند، fixtureها پاک شدند و هیچ پیامک/درگاه واقعی اجرا نشد.
- ممیزی مستقل queryهای UI نام‌گذاری صحیح فیلترها را تأیید کرد. تست HTTP controllerهای واقعی با ValidationPipe سختگیر اجرا می‌شود؛ سرویس‌های آن harness mock هستند و نتیجهٔ دیتابیس زنده محسوب نمی‌شوند.
- پس از اصلاح‌ها: فرانت در اجرای کامل ۶۸ فایل/۵۲۶ تست موفق؛ build فرانت موفق. ۱۰۰ تست HTTP فیلتر/سفارش/ورود محصول و تست تکمیلی وضعیت `PENDING` موفق؛ build بک‌اند موفق. ۳۹ تست هدفمند کارت‌های API، پیشنهادها و sync نیز موفق‌اند. ادمین پس از تغییر حذف، ۱۹ تست کاتالوگ موفق دارد. lint محدود بدون خطاست و هشدارهای تاریخی `any` بک‌اند باقی‌اند.
- API واقعی پس از راه‌اندازی build تازه: هر ۲۴ درخواست فیلتر خواندنی در کاتالوگ، سفارش، کاربران، پرداخت، کوپن، دارو/مراکز، audit/SMS، مرجع‌ها و گزارش/داشبورد پاسخ ۲۰۰ داد. داده‌های دارای نتیجه با مقدار فیلتر تطبیق داده شدند؛ جستجوی بی‌نتیجه آرایهٔ خالی داد. این matrix تغییری در داده ایجاد نکرد.
- نمایش محصولات در عرض ۱۲۸۰: فیلتر راست، سه ستون کارت، بدون overflow؛ عرض ۳۹۰: دو ستون کارت و فیلتر بازشونده، بدون overflow در هر دو حالت بسته/باز. نوع حیوان واقعی API در کارت‌ها دیده شد. جدول CSV فایل ۳۶ ردیفی مالک بررسی شد: ستون نام ۲۸۰ و برند ۱۹۰ پیکسل، ورودی برند داخل خانهٔ خودش و بدون overflow صفحه بود.
- gate نهایی بک‌اند پس از اصلاح تمام queryها: **۵۹ سوییت / ۷۶۱ تست موفق**. فرانت **۶۸ فایل / ۵۲۶ تست موفق**؛ اجرای کامل ادمین **۲۹ فایل / ۲۷۷ تست موفق** و سپس کاتالوگ **۱۹ تست موفق** برای تغییر تازهٔ بازخوانی بدون پنهان‌شدن جدول. build هر سه اپ و lint فرانت/ادمین و بخش‌های تغییرکردهٔ بک‌اند موفق‌اند؛ هشدارهای تاریخی `any` بک‌اند باقی‌اند.

پذیرش این مرحله روی MariaDB مجزای محلی است. پیامک واقعی، پرداخت واقعی و پذیرش MySQL تولید به نسخهٔ تأییدشدهٔ منتشرشده نیاز دارند. هیچ dependency یا migration تازه‌ای افزوده نشده است.
