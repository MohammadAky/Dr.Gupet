# بهینه‌سازی تحویل فرانت‌اند — ۱۳ اکتبر ۲۰۲۶

این اصلاح بر پایهٔ درخواست مالک برای بررسی گزارش Lighthouse انجام شده است. طراحی، قالب کارت‌ها، تعامل بنر، API و احراز هویت حفظ می‌شوند. حداقل نمایش لودینگ اولیهٔ لندینگ همچنان **۱۲۰۰ میلی‌ثانیه** است؛ برای بهترکردن امتیاز حذف نشده است.

## مبنا و محدودیت اندازه‌گیری

گزارش ارسالی مالک: Performance **68**، FCP **3.8s**، LCP **6s**، TBT **50ms**، CLS **0.002** و Speed Index **4.7s**. این اعداد، آزمون بعد از اصلاح نیستند. هشدارها شامل CSS مسدودکننده، کشف دیرهنگام تصویر اصلی، اندازهٔ تصاویر، محاسبهٔ مجدد چیدمان و JavaScript/CSS استفاده‌نشده‌اند.

مبنای حجم با `npm run build` تولیدی Vite اندازه‌گیری شد؛ نتیجهٔ Vite dev جایگزین این مبنا نیست. پیش از اصلاح، `/robots.txt` عمومی واقعاً HTTP 200 با `text/html` و بدنهٔ صفحهٔ SPA بود؛ فایل robots در دارایی عمومی وجود نداشت. بازبینی DOM عمومی نیز سه تصویر بنر eager، اولی با priority بالا و همسایه‌ها auto، بدون preload تصویر را نشان داد.

Chrome DevTools MCP در این نشست موجود نیست، PageSpeed وب پاسخ 403 داد و CUA به Resource Timing/trace دسترسی نداد. بنابراین امتیاز جدید، زمان بهبود FCP/LCP یا حذف کامل forced reflow گزارش نمی‌شود. نتیجهٔ حجم build و رفتار/DOM با امتیاز Lighthouse یکسان نیست؛ یک آزمون تازهٔ کنترل‌شده پس از انتشار هنوز لازم است.

## حجم قابل اندازه‌گیری

| دارایی تولیدی | قبل | بعد | تفاوت |
| --- | ---: | ---: | ---: |
| CSS مسدودکنندهٔ اولیه | 128,394 B | 94,048 B | 34,346 B کمتر؛ حدود **26.8%** |
| gzip همان CSS، با ابزار یکسان | 23,842 B | 18,327 B | 5,515 B کمتر؛ حدود **23.1%** |
| CSS صفحه‌های داخلی | همراه CSS اولیه | 34,347 B؛ gzip 6,627 B در chunk مستقل | تا بازشدن مسیر داخلی دریافت نمی‌شود. |

فرمت تصویر واقعاً WebP است؛ صرفاً پسوند عوض نشده. مشتق‌ها با sharp موجود، حفظ نسبت، بدون enlargement و quality 80 ساخته شده‌اند. فایل اصلی برای provenance و ارجاع‌های قدیمی باقی است.

| تصویر موبایل | اصل 720px | مشتق 480px | مشتق 720px |
| --- | ---: | ---: | ---: |
| خانواده | 98,064 B | 40,594 B | 83,040 B |
| غذا | 55,358 B | 22,436 B | 45,596 B |
| تشویقی | 85,638 B | 34,272 B | 70,650 B |

در DPR 1 و عرضی که نسخهٔ 480 انتخاب شود، مجموع سه عکس 97,302 B در برابر 239,060 B است؛ **141,758 B کمتر**. این جمع فایل‌هاست و ادعای کاهش همهٔ درخواست‌های واقعی یک بازدید نیست. برای DPR بالاتر ممکن است نسخهٔ 720 انتخاب شود. srcset مشتق‌های معتبر را فقط برای سه تصویر نسخه‌شدهٔ همین پروژه می‌سازد؛ URL سفارشی، بیرونی، queryدار، blob یا upload دیگر دست‌کاری نمی‌شود و srcset/sizes صریح فراخواننده مقدم است.

JavaScript اولیه تقریباً 315KB خام باقی است؛ هزینهٔ React، router، query و منطق مشترک همچنان وجود دارد. حدود 156KiB استفاده‌نشدهٔ گزارش مالک، مجوز حذف کورکورانهٔ کد مسیرها یا تغییر framework نیست. TBT گزارش‌شده 50ms است؛ این اصلاح تمرکزش تحویل CSS/تصویر و درخواست‌های ضروری است و وابستگی یا معماری جدیدی اضافه نمی‌کند.

preload HTML به کمپین پیش‌فرض فعلی اشاره می‌کند. صفحهٔ عمومی اکنون همان محتوا را می‌گیرد؛ ویرایشگر ادمین هنوز CMS مشترک منتشرشده نیست و HTML مستقل دارد. هنگام پیاده‌سازی انتشار CMS و تغییر/غیرفعال‌کردن اسلاید نخست، preload باید از تنظیم مؤثر تولید شود یا حذف شود تا تصویر پیش‌فرض بی‌استفاده دریافت نشود؛ بهینه‌بودن preload برای هر کمپین سفارشی ادعا نمی‌شود.

## پذیرش و مراحل باقی‌مانده

آزمون‌های هدفمند بنر، responsive asset، SafeImage و زمان لودینگ، typecheck/build و lint بررسی می‌شوند. علاوه بر شکل و عملکرد قبلی بنر، تغییر از صفر اسلاید فعال به چند اسلاید بدون resize و نبود layout read در حرکت‌های متوالی drag آزموده شده است. مسیرهای داخلی CSS را با import همان lazy module می‌گیرند، نه useEffect پس از paint. `account-polish.css`، fallback عکس، state، Header و کارت لندینگ در CSS مشترک باقی‌اند.

gate کامل نهایی فرانت‌اند: **۵۹ فایل / ۴۲۵ تست**، lint، TypeScript و build تولیدی پاس شدند. ادمین: **۱۹ فایل / ۱۱۸ تست**، lint و build پاس شدند. یک خطای تایپ اولیهٔ fixture تصاویر با استفاده از fixtureهای inline موجود Vite رفع و gate کامل مجدداً اجرا شد؛ تنظیمات سراسری TypeScript یا وابستگی جدیدی اضافه نشد.

در مرورگر تولیدی محلی با عرض ۳۹۰، تصویر فعال نسخهٔ 480، priority بالا و همسایه‌ها priority پایین داشتند؛ فقط CSS اولیه در لندینگ دریافت شد. ورود مستقیم به داروها CSS داخلی را دریافت کرد و preload تصویر بنر نداشت. عرض محتوای قابل استفاده ۳۷۵ و scrollWidth همان ۳۷۵ بود؛ تصویر خراب مشاهده نشد. فیلتر قیمت با دادهٔ API واقعی کار کرد؛ این پیش‌نمایش به API VPS وصل است و تست بک‌اند مستقل محلی محسوب نمی‌شود. فایل robots مشتری و ادمین هر دو واقعاً HTTP 200 با `text/plain` و سیاست درست داشتند.

این مرحله هنوز منتشر نشده است. انتشار فایل robots باید با HTTP `text/plain` و بدنهٔ واقعی روی هر دو دامنه بررسی شود؛ score/trace تازه، پذیرش cache/CDN و بررسی throttled شبکه پس از انتشار همچنان مستقل‌اند. این سند ادعای امتیاز 100، تست login/SMS واقعی یا اندازه‌گیری INP/LCP میدانی نمی‌کند.

منابع فنی اولیه: [بهینه‌سازی LCP](https://web.dev/articles/optimize-lcp)، [preload تصویر responsive](https://web.dev/articles/preload-responsive-images). راهنمای ابزار web-perf خوانده شد؛ مرحلهٔ trace به دلیل نبود Chrome DevTools MCP اجرا نشد.
