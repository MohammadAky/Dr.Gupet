# گزارش بازسازی لندینگ — ۱۳ اکتبر ۲۰۲۶

**به‌روزرسانی پس از تأیید مالک:** درخواست بعدی، کلینیک/داروخانه را به grid دوتایی و نمونه‌ها را به رکوردهای ماندگار بک‌اند تغییر داد و انتشار را مجاز کرد. وضعیت جاری و شواهد در [اصلاح نهایی و انتشار](PERSISTED_LANDING_RELEASE.md) است؛ توضیح‌های چهار کاروسل/نمونهٔ صرفاً JavaScript در این گزارش، تاریخچهٔ کاندید قبلی‌اند.

این گزارش مربوط به آخرین ساختار درخواستی مالک برای **لندینگ و مدیریت محتوای آن** است. بازبینی قبلی حساب کاربر، ورود، مدیریت و مشکلات هسته در [POLISH_REPORT](POLISH_REPORT.md) و [تحویل بک‌اند](POLISH_BACKEND_HANDOFF.md) حفظ شده‌اند. این مرحله طراحی دوبارهٔ پنل‌های حساب و مدیریت نیست.

کاندید محلی روی مبنای `a1525fa5eb71cfba796b7efda187a3521d7dab07` تهیه شده است؛ بررسی remote در آغاز این مرحله تغییر ورودی نشان نداد. کارهای محلی قبلی حفظ شدند. این کاندید هنوز commit، push یا منتشر نشده و تأیید مالک و پذیرش production باز است.

## نتیجهٔ قابل مشاهده

ترتیب صفحه: **نوار اطلاعیه ← منوی موجود ← بنر ← دسته‌بندی سگ/گربه/پرنده ← پرفروش‌ترین محصولات ← کلینیک‌ها ← داروخانه‌ها ← داروها ← فوتر**. بخش‌های اضافهٔ مسیر انتخاب و دعوت انتهایی حذف شده‌اند.

سه تصویرسازی اصیل برای بنر ساخته شده: خانم جوان بزرگسال خندان با سگ، گربه و پرنده در یک صحنه؛ بستهٔ غذای خیالی؛ بستهٔ تشویقی خیالی. نوشته‌ها و دکمه‌ها HTML فارسی‌اند و داخل پیکسل تصویر نیستند. نسخهٔ موبایل هر صحنه جداگانه بازآرایی شده تا صورت‌ها و بسته‌بندی کشیده یا ناقص نشوند. منبع و promptهای دقیق در [LANDING_ASSETS](LANDING_ASSETS.md) ثبت شده‌اند.

## رنگ، اجزا، عنوان‌ها و متن

هویت سبز جنگلی، کرم گرم و طلایی محدود حفظ شده است. بنر زمینهٔ کرم و متن سبز تیره دارد؛ این ترکیب در هر دو تم خوانا می‌ماند. تصویرها با همان خانوادهٔ رنگ ساخته شده‌اند. بخش‌های پایین صفحه از توکن‌های رنگ و سطح تم استفاده می‌کنند؛ تغییر رنگ سراسری یا کتابخانهٔ تازه اضافه نشده است.

یک `h1` برای اسلاید فعال، `h2` برای هر بخش و `h3` برای کارت‌ها استفاده می‌شود. متن فارسی با فاصله و ارتفاع خط مناسب، بدون فاصله‌گذاری مصنوعی حروف، نمایش داده می‌شود. تیترها و توضیح کارت‌ها محدودیت بصری دارند تا ردیف با متن طولانی از شکل خارج نشود. اقدام اصلی بنر یک دکمهٔ واضح است؛ مشاهدهٔ فهرست هر بخش هم کنترل مستقل دارد.

نمونه‌ها ادعای فروش، قیمت واقعی، مرکز واقعی یا توصیهٔ درمانی ندارند. قیمت‌ها «قیمت نمونه» هستند و کارت‌ها به فهرست عمومی مرتبط می‌روند؛ شناسهٔ جزئیات یا سفارش خیالی ساخته نشده است. معیار فروش در ادمین قابل انتخاب است، اما تا اتصال endpoint مربوط، ترتیب نمونه به‌عنوان آمار واقعی معرفی نمی‌شود.

## حرکت و دسترس‌پذیری

مطابق رویکرد Emil و Apple، حرکت برای توضیح تغییر وضعیت استفاده شده است. تصویر بنر هنگام اقدام با اشاره‌گر طی ۲۶۰ میلی‌ثانیه crossfade و نوشته طی ۲۲۰ میلی‌ثانیه با جابه‌جایی عمودی ۶ پیکسل ظاهر می‌شود. تغییر با صفحه‌کلید و حالت `prefers-reduced-motion` فوری است. چرخش خودکار و دکمهٔ pause/play وجود ندارد.

کاروسل‌ها اسکرول افقی بومی دارند؛ لمس به مرورگر سپرده شده و drag ماوس پس از آستانهٔ ۸ پیکسل فعال می‌شود. فلش‌ها در لبه غیرفعال می‌شوند. دکمه‌ها نام دسترس‌پذیر و هدف لمس مناسب دارند، نقطهٔ اسلاید وضعیت انتخاب‌شده را اعلام می‌کند و توضیح تصویر فعال برای فناوری کمکی وجود دارد. تغییر اسلاید فوکوس را جابه‌جا نمی‌کند. تصویر ناموجود fallback دارد.

این شواهد جای آزمون دستی با صفحه‌خوان، بزرگ‌نمایی ۲۰۰٪ یا لمس روی دستگاه فیزیکی را نمی‌گیرند؛ این موارد در این مرحله انجام نشده‌اند.

## مدیریت محتوای ادمین

بخش «محتوای صفحهٔ اصلی» برای نقش ADMIN اضافه شده است. موارد قابل ویرایش:

- فعال‌بودن، متن و لینک داخلی اطلاعیه؛
- افزودن، حذف، ترتیب و فعال‌بودن اسلایدها؛ عنوان، توضیح، متن اقدام، مقصد و توضیح تصویر؛
- تصویر دسکتاپ و موبایل، نقطهٔ تمرکز مستقل، پیش‌نمایش برش و خروجی WebP؛
- معیار رتبه‌بندی تعداد/مبلغ فروش پرداخت‌شده و بازهٔ زمانی؛
- عنوان و حالت نمونهٔ هر چهار بخش؛ کارت‌ها، ترتیب، تصویر، مقصد، متن، نشان و قیمت اختیاری.

برش دسکتاپ ۱۶:۷ با خروجی ۱۶۰۰×۷۰۰ و برش موبایل ۴:۵ با خروجی ۷۲۰×۹۰۰ است. تصویر کشیده نمی‌شود؛ نقطهٔ تمرکز قابل تنظیم است و فایل اصلی قابل دانلود می‌ماند. ورودی تصویر از نظر نوع واقعی، امکان decode و سقف ۱۰ مگابایت کنترل می‌شود. URLهای موقت هنگام جایگزینی و خروج آزاد می‌شوند.

پیش‌نویس کامل JSON نسخهٔ ۱ قابل خروجی و ورود است. چهار بخش الزامی‌اند؛ فایل قدیمی بدون این ساختار باید با پیام مشخص رد شود. لینک خارجی/نامعتبر، مسیر تصویر نامعتبر، شناسهٔ تکراری، مختصات نامتناهی و مقادیر اختیاری نامعتبر پذیرفته نمی‌شوند. پیش‌نویس ذخیره‌نشده محافظ خروج دارد.

**محدودیت مهم:** این ویرایشگر هنوز پیش‌نویس محلی است. خروجی JSON و تصویر واقعاً ساخته می‌شود، اما تغییر پنل پس از refresh یا خروج بدون export نگهداری نمی‌شود و روی لندینگ منتشر نمی‌شود. وضعیت «پیش‌نویس؛ منتشر نشده» صریح نمایش داده شده است. اتصال ذخیره/انتشار به سرور به کار بک‌اند نیاز دارد؛ دکمهٔ ذخیرهٔ نمایشی یا موفقیت ساختگی اضافه نشده است.

### بازبینی تکمیلی نهایی

- اصلاح ارتفاع بنر: ۱۲ تست هدفمند موفق، شامل transform والد، offset چندمرحله‌ای و resize هدر؛ lint و typecheck موفق. بررسی مرورگر پس از بارگذاری تازه: شروع بنر در ۱۷۲٫۸۷۵ و پایان در ۷۱۹٫۸۷۵ پیکسل برای قاب ۷۲۰ پیکسلی؛ اختلاف کسری زیر یک پیکسل ناشی از گردکردن offset است.
- اصلاح ورود JSON با کلید اضافی: ۱۳ تست هدفمند ادمین موفق؛ فایل نامعتبر رد و پیش‌نویس قبلی حفظ می‌شود و خروجی بعدی قابل استفاده است. lint، typecheck و build دوباره موفق. اجرای کامل ۸۰ تست مربوط به checkpoint پیش از این اصلاح است؛ عدد ۸۱ به‌عنوان اجرای کامل ادعا نمی‌شود.
- build نهایی ادمین: JavaScript اصلی ۴۲۵٫۲۵ کیلوبایت، gzip برابر ۱۱۷٫۰۰؛ CSS برابر ۶۹٫۶۸، gzip برابر ۱۳٫۳۸. اندازهٔ bundle جای سنجش Core Web Vitals نیست.
- اجرای نهایی r2 فرانت روی همین اصلاح‌ها: ۴۹ فایل / ۳۳۷ تست موفق؛ lint و typecheck کامل و build موفق با ۲۵۲ ماژول. JavaScript اصلی ۳۰۶٫۹۹ کیلوبایت، gzip برابر ۹۳٫۵۰؛ CSS برابر ۱۲۱٫۶۷، gzip برابر ۲۲٫۷۶. هشدار advisory مربوط به PLUGIN_TIMINGS مانع build نبود؛ خطای build گزارش نشد.
- مقایسهٔ manifest نهایی نشان داد هر ۲۰۸ ورودی source/public/config فرانت طی اجرای r2 بدون تغییر مانده‌اند؛ differences خالی است. شواهد با نام‌های `landing-final-test-result-2026-10-13-r2.txt` و `landing-final-test-manifest-2026-10-13-r2.json` در خروجی محلی بررسی حفظ شده‌اند.
- فاصلهٔ فلش و دکمهٔ تم در قاب واقعی موبایل و پس از اسکرول کوتاه بررسی شد. هر چهار کاروسل دسکتاپ عرض ۱۲۲۵ و کارت حدود ۲۹۲٫۶ پیکسل داشتند؛ عرض سند از عرض قاب تجاوز نکرد.
- خروج از حساب بررسی از رابط انجام شد و تنها دو هویت خصوصی و موقت همین آزمون در دیتابیس پذیرش محلی، با کنترل شناسه/نقش/نشان و در تراکنش، پاک شدند. داده‌های فروشگاه و سفارش‌های موجود حفظ شدند.
- پاسخ سلامت API محلی و proxy هر دو رابط HTTP ۲۰۰ بود. در بررسی پایانی فرایند watch بک‌اند دیگر روی پورت گوش نمی‌داد؛ خروجی کامپایل‌شدهٔ همان source با تنظیمات خصوصی محیط پذیرش دوباره اجرا شد و هر سه پاسخ سلامت تأیید شدند. این یک راه‌اندازی محلی بود؛ source بک‌اند تغییر نکرد.

## نیازهای بک‌اند و پذیرش باز

[پروندهٔ ۳۳](../../.issue/33-landing-content-sales-and-nearby-contract.md) شامل قرارداد لازم و شواهد فعلی کد است:

1. دریافت محتوای منتشرشدهٔ لندینگ و ذخیره/انتشار نسخه‌دار ADMIN با audit و کنترل هم‌زمانی؛ اطلاعیه، اسلایدها و همهٔ بخش‌ها باید در قرارداد باشند.
2. رتبه‌بندی عمومی محصولات از سفارش‌های **پرداخت‌شده** با شناسهٔ محصول؛ گزارش فعلی ادمین همهٔ وضعیت‌ها و snapshot نام را شامل می‌شود و معیار قابل اتکای پرفروش عمومی نیست.
3. نزدیک‌ترین کلینیک/داروخانه از کل مجموعه با مرتب‌سازی پیش از pagination؛ API فهرست فعلی مختصات ندارد. شاخهٔ موجود فرانت تنها یک مجموعهٔ محدود را با جزئیات دریافت‌شده مرتب می‌کند و نزدیک‌ترین مرکز کل پایگاه را تضمین نمی‌کند.
4. سیاست تصویر/آپلود/نسخهٔ منتشرشده و حفظ حریم خصوصی مکان. موقعیت تنها با اقدام کاربر درخواست می‌شود؛ در حالت نمونه هیچ درخواست موقعیت یا مختصات کاربر ارسال نمی‌شود.

در این مرحله source بک‌اند تغییر نکرد و نمونه‌ها در دیتابیس seed نشدند. پرداخت، ارسال SMS واقعی، nearest در کل دیتابیس، انتشار CMS و پذیرش VPS انجام نشده‌اند. وابستگی تازه، tracker یا سرویس معماری تازه اضافه نشده است. تصمیم‌ها در DEC-028 و قرارداد بصری در DESIGN_SYSTEM ثبت شده‌اند.

## راهنمای پیش‌نمایش محلی

صفحهٔ مشتری روی `http://127.0.0.1:5175/` و ادمین روی `http://127.0.0.1:5174/` اجرا می‌شوند؛ API محلی روی پورت ۳۰۱۲ است. برای ارائه، ابتدا بنرها و دسته‌بندی‌ها، سپس دو/چهار کارت هر بخش و drag را نمایش دهید. پنل ادمین را با حساب مجاز خودتان باز کنید و وضعیت منتشرنشده، ویرایش محتوا، برش و export را نشان دهید. حساب‌های خصوصی بررسی برای نمایش عمومی نیستند.

این نشانی‌ها فقط روی همین رایانه در دسترس‌اند. سرویس‌ها برای پیش‌نمایش روشن نگه داشته می‌شوند. هر انتشار بعدی نیازمند تأیید مالک، commit/push نسخهٔ تأییدشده و استقرار همان SHA با پشتیبان و پذیرش زنده است.
