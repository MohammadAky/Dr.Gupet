# اصلاح کاتالوگ و سبد مهمان — ۱۹ اکتبر ۲۰۲۶

مالک طرح را تأیید و تکمیل تغییرات و انتشار ابتدا روی VPS و سپس GitHub را مجاز کرد. قبل از انتشار، `main` گیت‌هاب و VPS روی `ec53f93590fe03e7694f0e8bc1b3eac0349e7264` بودند؛ کار محلی پیش از تطبیق در patch و کپی فایل‌های تازه خارج Git حفظ شد. توسعهٔ این مرحله فقط رابط‌هاست؛ backend، schema و dependency تغییری ندارند.

## نتیجهٔ رابط

- هویت Liquid Glass، انعکاس و مرز شیشه‌ای، سبز/طلایی و RTL حفظ شده‌اند. متن‌های لایت‌مود سبز خوانا و عنوان/legend دارای فاصلهٔ داخلی‌اند؛ تخفیف و «فروش ویژه» قرمزند.
- فهرست محصولات چهار ستون دسکتاپ و دو ستون عمودی موبایل دارد؛ جستجوی تکراری حذف شده است. فیلتر دسکتاپ فقط یک بخش باز دارد؛ دو ردیف اسلایدی موبایل و کشوی شیشه‌ای انتخاب‌ها را نگه می‌دارند. فیلترهای دارو/کلینیک/داروخانه نیز همین دسترسی فشرده را با قراردادهای قبلی دارند.
- API موجود در batchهای ۲۴تایی نزدیک viewport خوانده می‌شود؛ صفحه‌بندی عددی حذف، خطای ادامه/تازه‌سازی قابل بازیابی و شناسه‌های تکراری حذف می‌شوند. ردیف آخر با کارت ساختگی پر نمی‌شود.
- قیمت در سمت چپ و «تومان» سمت چپ عدد است؛ خط بالای قیمت حذف شده است. درصد از compareAtPrice واقعی محاسبه می‌شود. ناموجود قیمت/افزودن ندارد. دکمهٔ سبد از لینک کارت جداست؛ یک گزینه مستقیم و چند گزینه با انتخاب صریح کار می‌کند.
- جزئیات محصول گالری، اطلاعات و پنل خرید واکنش‌گرا دارد؛ داده یا امتیاز ساختگی اضافه نشده است.
- پاپ‌آپ مسیر مستقل ادمین و متن/عنوان اختیاری دارد. ورودی دستی URL تصویر حذف و آپلود/پیش‌نمایش/حذف جایگزین شده است. پاسخ کامل API آپلود به مسیر امن داخلی تبدیل می‌شود؛ همان تصویر پس از ذخیرهٔ واقعی بارگذاری شد.
- سبد مهمان با ذخیرهٔ ضروری مرورگر و خطای روشن ذخیره‌سازی کار می‌کند. بعد از ورود، تعداد مهمان جایگزین اقلام مشترک حساب و سایر اقلام حساب حفظ می‌شوند؛ این سیاست در رابط توضیح داده می‌شود. checkpoint، قفل بین تب‌ها، تطبیق با پاسخ واقعی و محافظ تعویض حساب جلوی تکرار کور POST و ورود زودهنگام به checkout را می‌گیرند.
- اعلان تنظیم‌شده روی همهٔ مسیرهای مشتری رندر می‌شود. ورود مسیر/فیلتر/fragment قبلی را حفظ می‌کند. CMS مشترک بین دستگاه‌ها همچنان نیاز جداگانهٔ پروندهٔ ۳۳ است.
- پنجره‌های هم‌زمان مالکیت مشترک قفل دارند: Escape فقط بالاترین را می‌بندد و بعد از آخرین پنجره فوکوس، inert و اسکرول بازیابی می‌شوند.

## شواهد و محدودهٔ آزمون

در مرورگر محلی با API، MariaDB و Redis واقعی، افزودن مهمان، حفظ پس از reload، ورود با رمز حساب آزمایشی موجود و بازگشت مستقیم با همان سبد به checkout موفق بود. سبد حساب محلی پس از آزمون به مقادیر پیشین بازگردانده شد؛ سفارش/پرداختی ثبت نشد. ورود از داروخانه نیز به همان صفحه برگشت. این شاهد حساب آزمایشی ADMIN در رابط مشتری است، نه پذیرش مستقل USER یا تحویل OTP.

مرورگر در عرض ۳۶۰ پیکسل دو ستون و نبود هم‌پوشانی قیمت/سبد را نشان داد؛ عرض scroll از viewport بیشتر نبود. دسکتاپ چهار ستون، فیلترهای بدون fill/خط داخلی، یک بخش باز و بارگذاری واقعی ۲۴→۲۹ قلم هنگام اسکرول بررسی شد. عنوان تحویل داخل کادر و متن اقدام غیرفعال در لایت‌مود خواناست. تصاویر غایب API با placeholder واقعی باقی‌اند؛ تصاویر مرجع دیجی‌کالا در پروژه کپی نشده‌اند.

gate محلی: فرانت **۷۲ فایل / ۶۱۴ تست** و ادمین **۳۰ فایل / ۳۰۴ تست** موفق‌اند؛ lint، TypeScript و build هر دو رابط و build بک‌اند بدون تغییر منبع موفق بودند. build ادمین هشدار اندازهٔ chunk حدود ۵۰۰KB دارد؛ خطای build نیست و ادعای اندازه‌گیری تازهٔ Lighthouse نداریم. آزمون‌های مستقل در حافظه/JSDOM دو رقابت بازتولیدشده را بررسی کردند: تداخل پنجره‌ها و تغییر تعداد بازیابی هنگام GET تب دیگر. این شاهد جای آزمون فیزیکی گوشی یا تضمین اتمیک بین دستگاه‌ها را نمی‌گیرد.

## نیازهای باز بک‌اند

- [پروندهٔ ۳۶](../../.issue/36-image-only-storefront-popup.md): فعال‌کردن پاپ‌آپ فقط‌تصویری/فقط یک متن هنوز با ۴۰۰ سرور رد می‌شود؛ پیش‌نویس غیرفعال تصویری واقعاً ذخیره شد. فرانت موفقیت صوری نشان نمی‌دهد.
- [پروندهٔ ۳۷](../../.issue/37-delivered-buyer-product-reviews.md): نظر، ستارهٔ ۱ تا ۵، صلاحیت خریدار تحویل‌گرفته و aggregate واقعی API/model ندارند.
- [پروندهٔ ۳۸](../../.issue/38-atomic-guest-cart-handoff.md): انتقال اتمیک و idempotent بین دستگاه‌ها نیازمند سرور است؛ محافظ‌های کلاینت معادل آن نیستند.

انتشار دادهٔ محصولات را وارد یا جایگزین نمی‌کند، seed و migration تازه ندارد. بکاپ پایگاه‌داده، uploadها، buildها، پیکربندی خصوصی و تصویر/ SHA قبلی برای rollback حفظ می‌شود. revision فایل‌های عمومی و label بک‌اند پس از انتشار با commit تطبیق داده می‌شوند. SMS واقعی و پرداخت واقعی آزموده نمی‌شوند؛ درایور پرداخت تولید disabled باقی است.
