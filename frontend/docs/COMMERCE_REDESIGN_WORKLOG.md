## شواهد اجرا

وضعیت نهایی محلی این نوبت: آمادهٔ مرور مالک، **منتشر نشده**. `HEAD` و GitHub main همچنان مبنای بالا هستند و index خالی است. بنا به اطلاع مالک VPS تمدید نشده و سایت خاموش است؛ این نوبت هیچ بررسی یا تغییر سرویس زنده انجام نشد.

- Frontend: **۶۵ فایل / ۴۸۲ تست پاس**؛ lint، typecheck و build پاس (۲۸۰ ماژول). اجرای کامل اولیه فقط یک انتظار قدیمیِ آستانهٔ ۱٫۵ میلیون را رد کرد؛ تست مرزی با ۵٬۹۹۹٬۹۹۹/۶٬۰۰۰٬۰۰۰ اصلاح شد و اجرای کامل نهایی پاس شد.
- Admin: **۲۳ فایل / ۱۷۹ تست پاس**؛ lint، typecheck و build پاس. سه تست جدید انتخاب عکس هاور، قفل درخواست و تلاش مجددِ فقط خواندنی را پوشش می‌دهند.
- Backend: **۵۱ suite / ۵۰۰ تست پاس**؛ build و TypeScript پاس؛ lint محدود به فایل‌های تغییرکرده بدون خطا با ۱۴ هشدار قبلی. schema، migration و dependency جدید ندارد.
- API/SQL مستقل: **۱۳ بررسی پاس / ۱ مسدود** روی MariaDB 10.4.32. عکس اصلی ثابت، ترتیب عکس هاور پایدار و append سالم؛ پاسخ مهمان ۴۰۱، کاربر ۴۰۳، انتخاب عکس اصلی/نوع نامعتبر ۴۰۰، عکس بیگانه ۴۰۴؛ داده‌های عمومی/علاقه‌مندی/پیشنهادها سازگار. ارسال مرزی و تغییر تعداد واقعاً در دیتابیس/API بررسی شد.
- مرورگر: ورود حساب آزمایشی، افزودن واقعی کالا، تایپ تعداد فارسی ۱۲ و سبد ۶ میلیون با ارسال رایگان، تحویل با نشانی ساختگی، فرم ورود و ثبت‌نام، گالری و تم‌ها بررسی شد. در ۳۶۰ و ۱۴۴۰ پیکسل overflow افقی در نماهای بررسی‌شده نبود؛ فرم ورود دسکتاپ با خطای مرکز کمتر از یک پیکسل وسط است. مقدار dirty سبد تا ذخیره/بازگردانی اجازهٔ checkout نمی‌دهد.
- فایل‌های ثابت/تصاویر از دارایی‌های WebP موجود استفاده می‌کنند؛ سبد خالی SVG اصیل داخل کد است. نمونه‌های این فاز فقط در دیتابیس مستقل محلی‌اند؛ داده‌های مالک حفظ شدند و هیچ seed تولید اجرا نشد.

### محدودیت‌ها و کار بعدی

۱. مرور و تأیید بصری مالک قبل از commit/push/publication، طبق AGENTS و مهارت پروژه.
۲. ثبت سفارش، اعمال کوپن روی سفارش و تأیید مالی واقعی در این محیط اثبات نشده: درایور غیرفعال پاسخ `503 PAYMENT_UNAVAILABLE` می‌دهد. تست واحد محاسبهٔ قبل از تخفیف جای آزمون پرداخت واقعی را نمی‌گیرد.
۳. حرکت دقیق flight، لمس فیزیکی و safe area / نوار مرورگر در PWA روی iPhone/Android واقعی هنوز باید بررسی شود. سبز بودن تمام viewport وب در مرورگر محلی دیده شد؛ این اثبات نوار سیستم عامل نیست.
۴. امتیاز Lighthouse جدید یا بهبود سرعت اندازه‌گیری‌شده ادعا نمی‌شود؛ متریال محدود است، blur متحرک و blur جدا برای هر کارت فهرست وجود ندارد. سنجش production build و دستگاه ضعیف قبل از انتشار انجام شود.
۵. پس از تأیید و دسترسی VPS تمدیدشده، backup دیتابیس، انتشار همان SHA در هر سه سرویس و آزمون زندهٔ ورود/SMS/نقش/پرداخت طبق قرارداد انتشار لازم است. اسناد این فاز به معنی پایان همهٔ فازهای مسیر توسعه نیست.
۶. صفحات کلینیک، داروخانه و دارو در مرورگر محلی باز شدند و فرم‌های فیلتر/horizontal overflow بررسی شد؛ دیتابیس مجزای این بررسی در این سه بخش رکورد ندارد. بنابراین ظاهر کارتِ پرشدهٔ این سه بخش در این نوبت با مرورگر تأیید نشده است؛ قواعد مشترک آن‌ها در ممیزی مستقل CSS بررسی شد. کاروسل مرتبط با سه محصول واقعیِ محلی و دو کارت در عرض موبایل، اسکرول داخلی و بدون overflow صفحه بررسی شد.
