مالک طراحی را تأیید کرد و اصلاح‌های زیر و سپس commit/push/استقرار را صریحاً درخواست کرد. این سند جانشین وضعیت «چهار کاروسل با کارت‌های ثابت فرانت» در [گزارش قبلی](LANDING_REBUILD_REPORT.md) است. بنر، تصویرسازی‌ها، رنگ، قلم، موشن و پنل پیش‌نویس ادمین حفظ شده‌اند. تصمیم فنی DEC-029 مرجع این مرحله است.

## رفتار موقعیت

دکمهٔ مشترک «استفاده از موقعیت من» در بخش کلینیک‌ها قرار دارد. توضیح پیش از اقدام می‌گوید موقعیت پس از اجازهٔ مرورگر برای محاسبهٔ فاصله به سرور ارسال می‌شود و ذخیره نمی‌شود. درخواست خودکار، watchPosition، نگهداری در مرورگر و مختصات در URL یا query key وجود ندارد.

`POST /clinics/nearby` و `POST /pharmacies/nearby` بدنهٔ عددی `{lat,lng,page,limit}` را می‌پذیرند. مقادیر نامتناهی، حدود جغرافیایی نامعتبر و فیلدهای نامجاز رد می‌شوند. تمام مقادیر کاربر پارامتر SQL هستند. رتبه‌بندی فاصلهٔ مستقیم و سپس شناسه پیش از LIMIT/OFFSET انجام می‌شود و `distanceKm` بازمی‌گردد. تماس شبکه از client مرکزی هر رابط عبور می‌کند.

رد اجازه، timeout، خطای یک منبع و نبود مرکز واجد مختصات، فهرست معمولی را قابل استفاده نگه می‌دارند. داروخانه‌های نمایشی مختصات و تماس واقعی ندارند و در نزدیک‌ترین‌ها قرار نمی‌گیرند. وجود شش نمونهٔ داروخانه به‌معنی شش داروخانهٔ واقعی در اطراف کاربر نیست. دادهٔ ده کلینیک فعلی مربوط به مشهد است؛ فاصلهٔ زیاد از شهر دیگر طبیعی است و عنوان «نزدیک» ادعای فاصلهٔ کوتاه نیست.

## نمونه‌های ماندگار

فیلتر دقیق `sampleOnly=true` و نشان `isSample` در API عمومی محصولات، داروها و داروخانه‌ها اضافه شده‌اند. لندینگ محصولات/داروهای نمایشی را از API می‌گیرد؛ کلیک به همان slug/شناسهٔ صفحهٔ کامل می‌رود. داروخانه و کلینیک چیدمان ثابت دارند؛ محصولات و داروها کاروسل باقی می‌مانند.

نمونهٔ محصول با فضای نام رزروشدهٔ `presentation-v1-`، نام و توضیح فارسیِ نمونه، تصویر اصیل و موجودی صفر ثبت می‌شود. حتی اگر مدیر موجودی آن را بالا ببرد، افزودن به سبد و رزرو اتمیک موجودی برای سفارش رد می‌شود. نمونهٔ دارو ترکیب، دوز یا توصیهٔ درمانی ندارد. برای داروخانهٔ نمونه تلفن، مختصات، تأیید مرکز یا رابطهٔ موجودی/تأیید دارو اختراع نشده است. صفحهٔ جزئیات نمونه تماس و نقشهٔ ساختگی نمی‌سازد.

ویرایش رکوردهای واقعی/نمونه از ابزارهای موجود «محصولات» و «دارو و مراکز» ادمین انجام می‌شود. ویرایشگر «محتوای صفحهٔ اصلی» هنوز پیش‌نویس منتشرنشده و خروجی فایل است؛ انتشار مشترک اطلاعیه/بنر/تنظیمات CMS و آمار عمومی فروش پرداخت‌شده همچنان نیاز مستقل [پروندهٔ ۳۳](../../.issue/33-landing-content-sales-and-nearby-contract.md) هستند. newest یا ترتیب نمونه آمار فروش قطعی نیست.

## عملیات دادهٔ بررسی‌شده

دو ابزار مستقل و کامپایل‌شده وجود دارند؛ هیچ‌کدام از startup، migration، `prisma:seed` یا `update.sh` فراخوانی نمی‌شوند:

```text
node dist/src/reference-data/operator.js --database=<exact-database> --allow-production --backup-confirmed
node dist/src/presentation-data/operator.js --database=<exact-database> --allow-production --backup-confirmed
```

ابتدا بدون `--apply` گزارش برنامه را بخوانید. تولید نیازمند `NODE_ENV=production`، نام دقیق MySQL و تأیید پشتیبانِ واقعاً انجام‌شده است. سپس `--apply` عملیات صریح را انجام می‌دهد. هر ابزار در تراکنش Serializable فقط ورودی‌های مفقود را می‌سازد و تعارض باعث توقف/rollback می‌شود؛ کاربران، سفارش‌ها، موجودی واقعی و ده کلینیک موجود بازنویسی نمی‌شوند. ابزار مرجع واژگان تأییدشدهٔ سگ/گربه/پرنده، ۲۳ نژاد و ۱۷ برچسب را با حفظ شناسه‌های موجود کامل می‌کند.

اجرای واقعی محلیِ ابزار نمونه: ۶+۶+۶ رکورد، بدون گونهٔ تازه؛ اجرای دوباره صفر درج. ده کلینیک حفظ، موجودی همهٔ variantهای نمونه صفر و مختصات همهٔ داروخانه‌های نمونه null بود. API واقعی محلی هر سه مجموعه و جزئیات را با نشان نمونه برگرداند. nearest با نقاط آزمون مصنوعی، pagination و فاصلهٔ عددی صحیح پاسخ داد؛ موقعیت خصوصی مالک برای این آزمون ارسال نشد.

## شواهد فنی

- فرانت: اجرای کامل ۴۹ فایل / **۳۴۴ تست موفق**، lint، typecheck و build موفق؛ ۲۱۱ ورودی طی gate بدون تغییر بودند.
- در بازبینی مرورگر، شناسهٔ داخلی انگلیسی SAMPLE از متن نمونهٔ جزئیات دارو حذف شد؛ داده و رفتار واقعی تغییر نکرد. پس از این اصلاح متنی، هشت تست موجود جزئیات و lint همان فایل موفق شدند و build انتشار دوباره ساخته می‌شود؛ manifest اجرای کامل مربوط به پیش از همین اصلاح کوچک است.
- بررسی بصری واقعیِ نسخهٔ منتشرشده نشان داد ترکیب aspect-ratio و max-height، عرض خودکار figure کارت دسکتاپ را کوچک می‌کند. عرض قاب عکس در grid ثابت صریحاً ۱۰۰٪ شد؛ ارتفاع محدود و چیدمان دو ستون حفظ می‌شوند. این اصلاح CSS با مرورگر و build انتشار بررسی می‌شود و رفتار API، داده و تست‌های منطقی را تغییر نمی‌دهد.
- ادمین: اجرای کامل ۱۴ فایل / **۸۱ تست موفق**، lint، typecheck و build موفق.
- بک‌اند: اجرای کامل ۴۴ مجموعه / **۳۷۹ تست موفق**؛ build و ESLint خواندنی با صفر خطا موفق. ۳۱۰ هشدار ساختاری موجود باقی است و پنهان نشده است.
- نخستین اجرای کامل بک‌اند یک fixture قدیمیِ داروخانه بدون `name` داشت؛ fixture واقعی‌تر شد و اجرای کامل مجدد موفق بود. لاگ شکست اولیه حفظ شده است.
- ابزار مستقل مرجعِ تولید بعد از این gate افزوده شد: **۲۰ تست متمرکز در دو مجموعه موفق**، build و lint صفرخطا موفق. fixture منطبق با سه slug فارسی VPS ثابت کرد ۲۳ نژاد و ۱۷ برچسب به شناسه‌های فعلی متصل می‌شوند و اجرای مجدد صفر درج دارد؛ شمارش اجرای کامل قبلی شاهد تغییر بعدی نیست.
- خرید نمونه حتی با stock=20 در MySQL و تراکنشِ همواره برگشت‌خورده رد شد؛ هیچ سفارش یا پرداخت واقعی ساخته نشد.

## انتشار و حدود پذیرش

پیش از انتشار، نسخهٔ قبلی سرور با مبنای `a1525fa` و GitHub تطبیق داشت و checkout پاک بود. هر دو migration موجود اعمال شده بودند. پاسخ سلامت و HTTPS دو دامنه موفق و دادهٔ عمومی سرور شامل ده کلینیک و صفر محصول/دارو/داروخانه بود. از دیتابیس، تنظیم nginx و build/image قبلی پشتیبان خصوصی گرفته شد. پرداخت تولید `disabled` است و فعال‌کردن درگاه جزو این مرحله نیست.

Nginx خروجی نسخهٔ جداگانه‌ای را سرو می‌کند؛ ساخت dist در checkout به‌تنهایی سایت را عوض نمی‌کند. انتشار باید source همان SHA تأییدشده، build مشتری/ادمین از آن SHA با `VITE_API_BASE_URL=/api/v1`، تصویر بک‌اند همان SHA و ترفیع همان buildها را انجام دهد. واژگان و نمونه‌ها عملیات دادهٔ دستیِ جداگانه پس از پشتیبان هستند، نه seed خودکار تولید. رکورد SHA، checksum، نتیجهٔ عملیات و پذیرش زنده در شواهد تحویل انتشار نگهداری می‌شود.

آزمون واحد، سلامت HTTP یا بررسی تنظیم `smsir` به‌معنی تحویل واقعی SMS یا ورود موفق صاحب حساب نیست. پرداخت واقعی، مشکل هم‌زمانی لغو سفارش و سایر موارد امنیتی قبلی در `.issue` همچنان مستقل‌اند. تغییرات طراحی این مرحله آن موارد را بسته اعلام نمی‌کنند.
